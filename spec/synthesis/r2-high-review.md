# Adversarial review — round 1 merged synthesis

## Part 1 — Fork rulings

**1. Crate granularity → ~10–12, not 17–20.** Crates in this design exist to firewall a *privilege* or a *dependency* (`cv-engine` = the only `Command` owner; `cv-core` = frozen contract; `cv-fixtures` = dev-dep; `cv-widgets` = rune-rev firewall) — not to give a lane a home. Modules are already pure view-model producers (`*Model` data, no rune imports); a directory under `cv-app/src/modules/` plus ownership-by-path gives the same merge isolation a crate does, without multiplying the two files that serialize through L0 anyway (workspace `Cargo.toml`, dep edges). Per-surface crates buy compile-time enforcement that `cargo-deny` bans + review already provide, at the cost of slower builds and harder cross-surface refactors. If `cv-app` genuinely gets fat, split *one* `cv-modules` crate — not seven.

**2. `Noun` kind → open string, but `Other(String)` is the worst option on the table.** A sealed enum with `Other` delivers false exhaustiveness: a lane's new noun kind arrives as `Other`, compiles fine, and silently hits the `_ =>` arm in every surface — the same silent degradation as open strings, *plus* a central enum edit. Open string wins, but only with three guardrails the merged design hasn't stated: (a) a `cv_core::nouns` constants module so `"finding"` is spelled in one place, (b) a noun-view registry with a defined generic fallback renderer, and (c) a test asserting every produced kind has a registered view. That gets you lane independence and a deterministic (test-level, not type-level) completeness check.

**3. Module rail → domain-oriented, decisively.** Verbs are commands, not places — users don't *inhabit* "Inspect," and "Inspect" the module collides with the inspector drawer that exists in every module (same word, two meanings). Verb rails force a mode switch for exactly the cross-module navigation this app lives on (finding → page, note → page). The vision doc and every lane brief are already domain-shaped; adopting verbs would rewrite L3–L7 for a metaphor gain nobody validated. Keep Pages/Research/Audit/Publish/Activity; verbs live in the command palette and inspector actions. Max's verb framing contributes one keeper — the Findings mailbox and Preflight gate — which survive fine as the Audit module and a publish gate.

**4. `cv-cli` → redundant as designed; salvage the two real use-cases.** "Every lane exercisable in CI" is already satisfied by `cargo test -p` + headless rune with scripted input — a CLI adds a *lower*-fidelity harness, not a missing one. The two things it smuggles in that are real: `doctor` ("your boris speaks a contract I don't know") must live **in the app** — users can't run xtask — and fixture regeneration belongs in `xtask` (dev-side tooling, already in high's design). Ship no user-facing `cv` binary unless the owner actually wants scriptability; nobody asked for it.

**5. Smart mailboxes → v1, late wave.** It's already half-committed: L6's nav includes "saved views" and the Findings mailbox is "smart-filterable" — the delta is a saved-predicate store plus a small editor UI, not a new subsystem. Crucially it's a *leaf*: nothing depends on smart mailboxes, so it can land after findings/notes exist and slip to v2 cleanly without breaking anything. Scope it to a closed algebra (~6 operators: field eq/contains/in + and/or/not), not a query language — the discarded jq-DSL instinct applied at UI scale is still wrong.

**6. Store → rusqlite (bundled), and the decision rule is "predicates in v1 → sqlite."** The query surface *is* the product — smart mailboxes, note↔page backlinks, and findings triage are all predicates over stored documents — and redb pushes secondary-index hand-rolling into every lane's namespace, fragmenting query logic into per-lane bug farms. SQLite concentrates that discipline in `cv-store`, where lanes declare schema + indexes in migrations, and FTS5 makes L6's deferred full-text free instead of a second store. JSONL earns a role only as the append-only evidence trail inside `.cv/` (inspectable, diffable), not the primary store. Had smart mailboxes been v2, redb would be defensible — they aren't.

## Part 2 — The two weakest spine points

**A. Watch-stream-as-truth, with no snapshot/resync authority.** Every module derives state "only from `EngineEvent` streams + store reads" — so the app's model of the project is a fold over a stderr pipe. But that pipe is the flakiest component in the system: L1's own spec *requires* surviving malformed NDJSON lines (a tolerated drop = silently wrong state), `tokio::broadcast` receivers get `Lagged` and lose events silently, watch exits permanently on `recoverable:false`, and app restart/sleep mid-session leaves no replay at all. There is no `Engine::snapshot()` — no verb that re-reads `.boris/graph.json` + last reports and declares "this is disk truth; events are deltas on top." This breaks on day one of dogfooding: close the laptop mid-watch, reopen, ghost diagnostics forever. Boris's own `boris-editor` contract solved this exact problem with a bounded buffered event ring + `?after=` resumption cursor — the pattern exists upstream and the merged design reinvented the stream without the resync.

**B. "Frozen, append-only `cv-core`" presumes the contracts were derived correctly — they weren't.** All three derivations were blind, and `cv-core` is a reverse-engineered mirror of a *moving* upstream with ~7 schemas. Every contract miss in practice resolves to one of two bad outcomes: permanent additive garbage (`EngineEvent2`, `run_v2`, parallel `Query` types accreting), or a serialized contract PR that stalls every lane — which makes L0 not just first but *permanently on the critical path*, quietly negating the parallelism the freeze was meant to buy. And there's a proven instance already inside the frozen surface: `ContentWriter` "validates closed frontmatter + parent existence BEFORE writing" — i.e., it **reimplements Boris's frontmatter grammar in Rust**, a direct violation of pillar 1 ("never reimplement Boris semantics") that rots the moment the grammar evolves. The honest implementations are staged-write + `boris validate`, or fingerprinted save + let the next build judge — neither of which is what contracts.md specifies. The fix isn't a stronger freeze; it's a *cheaper amendment process*: version `cv-core`, plan an explicit "contract hardening" wave between stub-integration and real-engine integration, and stop pretending wave-0's guess is load-bearing forever.

## Part 3 — The hole hunt

1. **`boris-editor` exists, and three independent agents missed it.** Boris ships a normative, conformance-tested loopback host (`docs/contracts/editor-host.md`, `boris-editor/0.1.0`) built for exactly this app shape: managed watch daemons, allowlisted `/api/commands/run`, **fingerprinted atomic saves** (SHA-256 + mtime — solves the file-changed-under-buffer problem for free), buffered events with an `?after=` cursor, `/api/authoring` (the sanctioned completion surface), and `/api/recovery` snapshots. Whether to build on it is a real fork the spec never asked — and there are legit reasons to decline (`watch_json`/`validate_watch` probes are "always false on Windows," an unversioned closed contract, HTTP+token plumbing, and secrets-over-stdin can't ride its JSON API). But "we spawn raw boris and hand-manage sessions" currently reinvents a tested supervisor by accident, not by decision. At minimum the spec must (a) rule on it explicitly, and (b) steal its proven mechanisms: fingerprint discipline in `ContentWriter` and a resumable event cursor.

2. **Note→page provenance is impossible as specified.** Boris's frontmatter key set is closed — unknown keys are a hard `EFRONTMATTER` (`frontmatter.md`: "no silent extras for forward compatibility"). L6's `x-capture-vector-note: <id>` will fail validation on every promoted page. The carrier must move: a `.cv/` sidecar map (note id → page id/path), or a body-level HTML comment (body bytes are verbatim, so it survives — but pollutes `dist/`). Pick the sidecar; it also survives page renames better than inline keys.

3. **Fixture drift mechanics are half-designed.** "Captured once" + `.meta.toml` + pinned hashes detects staleness but provides no recovery path: a Boris pin bump invalidates *every* fixture at once, serially through the Engine lane — a thundering herd at the worst moment. Missing: a fixture *format* schema version (so capture-format changes don't silently invalidate every lane's pinned hash), `xtask fixtures refresh`, and a CI job running the `#[ignore]`d live smoke tests on every pin bump — currently nobody is scheduled to run them ever.

4. **`.cv/` has no schema version or migration runner.** Finding lifecycles, snoozes, publish runs, and notes accumulate across app versions from day one — the first upgrade either corrupts user state or can't ship. `cv-store` needs `schema_version` + a migration chain in v1, not "when we need it." Related: snooze/dedup keys ride `PageId`/paths that change on reparent — a page move silently resurrects snoozed findings unless keys are content- or id-stable.

5. **Multi-window state is owned by nobody.** L2 ships "multi-window abstraction stubs" and L7 immediately needs two windows bound to one buffer entity — but nothing answers: which window's `Selection` wins the inspector, what closing-a-dirty-window means, whether rune headless can even simulate a second window, and how single-writer `AppState` dispatches across windows. This is a concrete L2↔L7 collision landing in the same wave, discovered at integration, not in the contract.

6. **No scale envelope — and "nothing is filtered" is a loaded gun.** L3 mandates Activity drop *nothing*; the audit budget is "<100 ms for *fixture-size* sites." A real publication (5k pages, watch rebuilds every few seconds, diagnostics rivers, `dist/` artifact lists) drowns the broadcast bus and every list view simultaneously. State the envelope (pages, diagnostics/sec, artifacts), require virtualized lists, and let the actor coalesce event bursts — or the "sacred diagnostics, nothing filtered" rule breaks the app before it breaks the spec.

7. **Diagnostic spans are build-version-relative; the editor buffer has moved on.** Diagnostics arrive with `line`/`column` computed against the *last build's* file contents while the user's typing has already shifted every position — gutter marks land on wrong lines and there's no staleness concept. Diagnostics need a version tag (the build/file hash they were computed against) and the editor needs a stale-diagnostics policy (map via diff, or mark dim until next build). Boris's fingerprint mechanism is the obvious carrier.

8. **Wave-0's "thin" L0 is actually the deepest item.** Fixture *capture* requires a real pinned Boris, authored stunt corpora (`happy/`, four `broken-*`, two publish scenarios), and recorded watch sessions — that is the slowest, most failure-prone deliverable, and all seven lanes gate on it. Sequence it: land contract stubs + `StubEngine` + the `happy/` corpus first to unblock lanes, then let lanes contribute their own `broken-*`/publish corpora additively. Otherwise "L0 merges, everyone starts" is a fiction — it's "L0's fixture sprint ends, everyone starts."

Two smaller ones worth naming: keychain-in-CI is unspecified (`keyring` has no backend in headless CI — the canary-secret test needs an explicit mock); and the advisory-vs-authoritative preview divergence will be the app's permanent "preview ≠ publish" bug farm — budget high's proposed parity check (`xtask` diffing Oliver fragments vs Boris-emitted bodies) as a standing lane, not a nice-to-have.
